# Orchard Core Video Producer

Every Orchard Core video looks and sounds the same: the same resolution, branding, layout, voice, captions, and
encoding. This skill holds that specification and the scripts that apply it. **Don't change the specification for a
single video.** If it must change, change it here, in `scripts/brand.py`, `scripts/narrate.py`, `scripts/assemble.py`
and `scripts/recorder/Scene.cs`, and in `references/specs.md`, so every later video follows.

This skill lives in the `OrchardCMS/OrchardCore.Videos` repository. Each video is a folder in `videos/<slug>/` that
keeps everything needed to make it again (storyboard, slides, recorder scenes, narration timings, captions, YouTube
metadata) and nothing that can be made again or is too large: **the MP4 is never committed**. It is published to the
Orchard Core YouTube channel (https://www.youtube.com/@OrchardCore), and the documentation (https://docs.orchardcore.net/) embeds it from there.

`examples/secrets-module/` is a worked example: the storyboard and slides of the Secrets module overview. Read it before
writing a new one, and copy `templates/video/` (a `video.json` and a `README.md`) to start a video's folder.

## The specification, in short

| | |
|---|---|
| Output | 1920x1080, 30 fps, H.264 (`-preset veryslow -crf 30 -tune stillimage`, more reference frames), AAC 48 kbps mono, `+faststart` |
| Recording | Chromium at 1536x864 CSS pixels, device scale 1.25, light color scheme, en-US, shown at 1728x972 in a green frame |
| Branding | Dark background with green glows, the Orchard Core logo (white name, green symbol, `branding/OrchardCoreLogo.png`), Open Sans from `branding/fonts` |
| Colors | Green `#41B670` (accents, frame, pills, highlights, clicks), dark green `#1D5B36`, charcoal `#404041`, gray `#C6C6C6`, white |
| Voice | `en-US-AndrewMultilingualNeural`, rate `+2%`, through `edge-tts` 7.3.1 or later: the same voice in every video |
| Structure | Opening card, numbered chapters (chapter card + slides or recordings), closing card |
| Captions | WebVTT and SRT, from the narration, at most about 13 words each |

The full specification, with every value and the reasons behind them, is in `references/specs.md`.

## Prerequisites

- Python 3.11+ with `pip install pillow pygments imageio-ffmpeg "edge-tts>=7.3.1"` (ffmpeg comes with `imageio-ffmpeg`).
  Older `edge-tts` releases are refused by the speech service with HTTP 403.
- .NET 10 SDK, for the recorder (Playwright for .NET; run `pwsh <bin>/playwright.ps1 install chromium` once).
- A throwaway local Orchard Core site with realistic, fake data to record (a checkout of `OrchardCMS/OrchardCore`): see `references/recording.md`.
- Internet access for the voice (`edge-tts` calls the Microsoft Edge speech service).
- For publishing: `pip install -r tools/youtube/requirements.txt`, and the one-time sign-in in `tools/youtube/README.md`.

## Workflow

### 1. Create the video's folder

`videos/<slug>/` is the workspace: the scripts read and write it, and `.gitignore` keeps what they generate (audio,
recordings, frames, builds, MP4s) out of git. Commit only what is listed under "What a video folder keeps" below.

```
videos/<slug>/
  README.md         what the video covers, and how to record it again (the site, the seed data)
  video.json        the YouTube title, description, tags, chapters, links, playlists, and the YouTube id once published
  thumbnail.jpg     the YouTube thumbnail: the opening card (build/00-intro.png) saved as JPEG
  storyboard.json   the chapters, clips and narration (see references/storyboard.md)
  slides.py         the slides, if the storyboard has "slide" clips
  recorder/         your clips: Scenes.cs (and Scenes.*.cs), one method per "clip" of the storyboard
  durations.json    generated by narrate.py: kept, so the recorder can run without generating the voice again
  <output>.srt/.vtt generated by assemble.py: kept, for YouTube captions
  audio/ clips/ build/ shots/ <output>.mp4      generated, never committed
```

Start from a copy of `templates/video/` (it holds a `video.json` and a `README.md` to fill in), the storyboard and slides of
`examples/secrets-module/`, and `scripts/recorder/Scenes.cs` for the scene skeleton.

### 2. Write the storyboard and video.json

Read `references/storyboard.md` first. In short:

- Write for the long term: say "the X module", never "the new X", "now", "in this release", or version numbers, so
  the video stays accurate for years.
- One idea per step, one to three sentences, spoken in the present tense. A step is what the viewer sees while it plays.
- Chapters: why it exists, how it is organized, each task in the order a user does them, how to extend it.
- Name UI elements exactly as they're labeled on screen. Check the labels in the code or on the page first.
- A video for the user manual shows the feature and how to use it in the admin UI. Leave code, JSON and
  `appsettings.json` snippets, and "extend it" chapters, to the developer documentation and the videos that back it.

`video.json` holds what YouTube shows. Write the title (at most 100 characters, "<Feature>: <benefit> | Orchard Core"), a description that says the problem, the solution and what the video covers, tags, hashtags, and links
to the documentation pages. The chapters are filled in by `youtube.py chapters` after assembling.

### 3. Generate the narration

```bash
python .agents/skills/orchardcore-video-producer/scripts/narrate.py videos/<slug>
```

It writes `audio/` and `durations.json`. Run it again after any change to the text: only the changed steps are
generated again. **Record after narrating**, since the recorder holds each step for the length of its narration.

If the voice mispronounces a word, add it to `SPOKEN` in `scripts/narrate.py` (for every video) or to `"spoken"` in
the storyboard (for this one). The captions keep the written form. "ASP.NET" is already spoken as "A.S.P. .NET".
Spell an initialism with dots and no spaces ("C.S.V."), never with commas. **Have a person confirm a new spelling
before using it**: check it with `scripts/pronounce.py`, which shows the words the voice speaks and the gaps between
them, and can save a few seconds of audio per candidate spelling. Rebuilding a whole video to try a spelling wastes
minutes per attempt.

### 4. Record the clips

Write one method per "clip" in `videos/<slug>/recorder/Scenes.cs`, with one `scene.StepAsync("<step id>", ...)` per
step, in the storyboard's order. A video can also define `public static Task PrepareAsync(IBrowser browser)` to seed
the site (enable features, save settings, create records) outside the capture. See `references/recording.md` for the
site to record, the scene API, and the pitfalls. Build the shared recorder with the video's scenes, then run it:

```bash
cd .agents/skills/orchardcore-video-producer/scripts/recorder
dotnet build -c Release -p:VideoScenes=C:/path/to/OrchardCore.Videos/videos/<slug>/recorder   # forward slashes in Git Bash
export VIDEO_ROOT=<repo>/videos/<slug> VIDEO_BASE_URL=http://localhost:5010
export VIDEO_INIT_SCRIPT=<path>/mask.js   # optional, kept outside the repository: replaces leftover real names
<bin>/Recorder setup          # logs in, once (VIDEO_USER_NAME / VIDEO_PASSWORD), and saves state.json (git-ignored)
<bin>/Recorder prepare        # runs the video's PrepareAsync, if it has one
<bin>/Recorder record all     # or the names of some clips
python .agents/skills/orchardcore-video-producer/scripts/review.py videos/<slug> <clip>
```

`<bin>` is `%TEMP%/ocvideo/bin/Release/net10.0`. Look at every contact sheet (`shots/<clip>.jpg`) before
assembling: the frame at the end of each step must show what its narration describes, with no error message, empty
list, or real person's data.

A step that waits on something slow, such as a model's answer, can cut the wait out of the video with
`scene.OffCameraAsync(() => <wait>)`: frames are dropped and the time is taken out of the clip, so the video jumps
from the moment before the wait to the moment after it. Make the wait's condition specific to the new state: one
that the page already meets returns at once, and the wait then happens on camera.

### 5. Assemble

```bash
python .agents/skills/orchardcore-video-producer/scripts/assemble.py videos/<slug>
python tools/youtube/youtube.py chapters <slug> --build videos/<slug>/build
```

`assemble.py` writes `<output>.mp4`, `.vtt` and `.srt`, and a short video for every chapter with a `"short"` name. It
prints the length and size. Don't raise the CRF to make a file smaller: it blurs small text. Extract a few frames with
ffmpeg and look at them: a recording, a slide, and a card. `chapters` writes the chapter times into `video.json`.

### Reels: screencasts without narration

Silent screencasts that already exist (the walkthroughs the documentation used to carry) aren't narrated again: they
are joined into a **reel**, one video per area with one chapter per screencast, in the same look (cards, frame,
encode). `reel.json` lists the screencasts by their path in a source repository at a fixed commit, so the reel can be
built again after the files are gone from that repository (for example, the `.mp4` screencasts under `src/docs` in
`OrchardCMS/OrchardCore`):

```bash
python .agents/skills/orchardcore-video-producer/scripts/reel.py videos/<slug> [--source <local clone>]
```

It writes `<slug>.mp4`, `thumbnail.jpg`, the chapters and length into `video.json`, and each screencast's `start` and
`end` (whole seconds: every screencast starts and ends on one) into `reel.json`, for the documentation's
`<!-- video:<slug> start=... end=... -->` markers of the documentation. Reels are `unlisted`, in the "Orchard Core
Walkthroughs" playlist: they back the documentation pages rather than stand on the channel.

YouTube shows chapters only when there are at least three, the first at `0:00`, and each is at least 10 seconds long;
otherwise it shows none. `reel.py` folds the opening and closing cards into the first and last chapters for that reason.

### 6. Check for private data

Before publishing, OCR the video at one frame per second **and at every scene change** (ffmpeg
`select='gt(scene,0.02)'`), then at 5 frames per second, and search the text for real names, email addresses, phone
numbers and tokens. One frame per second misses a flash: a page that shows real names for a moment before its mask
applies. Fix the site or the mask, and record again; never publish a video that shows real data.

When recording again isn't possible (the screencasts a reel reuses), `scripts/redact.py` hides the words instead. It
OCRs every frame (Windows OCR), pixelates what matches `--pixelate`, and paints a fake name over a real one with
`--replace "Jordan Rivera=John Smith"`, in the original's size, color and weight. Use `--ocr-scale 2` for small
text. In a reel, give the chapter a `"redact"` spec so every rebuild applies it, then scan the result again: OCR can
miss a word on some frames, so redaction usually takes two or three passes.

### 7. Publish

- **YouTube**: merge the video's folder to `main`, then create the draft release of its next version with the MP4:

  ```bash
  python tools/youtube/youtube.py release <slug> --file videos/<slug>/build/master.mp4
  ```

  Watch the video on the draft release, then publish the release. The **Publish video** workflow uploads it with the
  title, description (with chapters and links), tags, captions, `thumbnail.jpg` and playlists of `video.json`, records
  the YouTube id back in `video.json` and the README index, and opens the documentation pull request. A re-recording
  is the next version (`<slug>/v2`): it is a new YouTube video, and the previous one becomes unlisted. To change the
  title or description later, edit `video.json` and merge (the **YouTube metadata** workflow pushes it), or run
  `python tools/youtube/youtube.py update <slug>`.
- **Documentation**: the Orchard Core repository never stores videos (no MP4 under `src/docs` for a video that is on
  YouTube). The docs (`src/docs` of `OrchardCMS/OrchardCore`, built with MkDocs into https://docs.orchardcore.net/)
  embed a YouTube video with the `<iframe>` the other videos of the docs use (`youtube-nocookie.com`). A page marks
  where a video goes with a comment on its own line, and the publish workflow's pull request fills in the iframe
  after it with the video's YouTube id:

  ```html
  <!-- video:secrets-module -->
  <!-- video:secrets-module start=99 end=146 title="Video of creating a secret" -->
  ```

  Put the first marker under the introduction of the feature's page, and give a task's section its own marker with
  `start` and `end` (whole seconds, from the chapter times) to play one chapter. A marker renders nothing until the
  video is published, so the feature's own pull request can add it first. Introduce it with one sentence that says
  what it covers, without "new". Record the pages in `video.json`'s `embeddedIn`. To fill in the iframes by hand, run
  `python tools/youtube/youtube.py docs-embed <slug> --docs <OrchardCore checkout>/src/docs`, and check the page
  with `mkdocs build`.
- **This repository**: commit the video folder, and the README index (`python tools/youtube/youtube.py index`).

### 8. Clean up

Stop the site you recorded (by its process ID, never by image name). Keep `build/master.mp4` somewhere outside git
(it is the best copy to upload again) until the video is published.

## What a video folder keeps

| Kept in git | Not kept |
|---|---|
| `README.md`, `video.json`, `thumbnail.jpg`, `storyboard.json`, `slides.py`, `recorder/Scenes*.cs`, seed data files, `durations.json`, `<output>.srt`, `<output>.vtt` | MP4s, MP3s, `audio/`, `clips/`, `build/`, `shots/`, `state.json`, mask scripts with real names, `App_Data` copies, credentials |
